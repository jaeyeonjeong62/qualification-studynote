# 4.1 LLM 기반 테스트 인프라를 위한 아키텍처 접근법

## 4.1.1. LLM 기반 테스트 인프라의 주요 아키텍처 구성요소와 개념

- (K2) LLM 기반 테스트 인프라의 주요 아키텍처 구성요소와 개념을 설명한다.

---

LLM 기반 테스트 인프라는 자동화, 추론, 의사 결정을 향상시키기 위해 LLM을 테스트 프로세스에 통합한 시스템을 말한다.
LLM 기반 테스트 인프라의 일반적인 아키텍처는 LLM과의 안전하고 효율적인 상호작용을 용이하게 하는 다중 구성요소 설계를 따른다. 이 아키텍처는 프론트엔드와 백엔드 구성요소, 그리고 외부 데이터 소스와 통합된 LLM으로 구성된다:

- **프론트엔드**: 테스터가 쿼리나 명령어를 입력해 시스템과 상호작용하는 사용자 인터페이스 역할

- **백엔드**: 사용자 입력을 처리하고 인증, 데이터 검색, 프롬프트 준비, LLM과의 상호작용과 같은 중요한 기능을 관리

- **LLM**: API를 통해 접근하는 서드파티 서비스 또는 맞춤형 사내 모델로 호스팅될 수 있으며, 구조화된 프롬프트를 기반으로 응답을 생성한다.

이 아키텍처는 LLM 및 다중 소스 백엔드와 같은 지능형 처리 구성요소를 통합함으로써 전통적인 클라이언트-서버 모델을 뛰어넘는다:

1. LLM은 단순한 서버가 아니라 테스트웨어를 기반으로 해석하고 추론하는 지능형 처리 구성요소이다.

2. 스크립트화된 응답을 따르는 규칙 기반 챗봇과 달리, LLM 기반 테스트 인프라는 요구사항이나 코드 또는 테스트 결과와 같은 컨택스트로부터 동적으로 테스트 인사이트를 생성한다.

3. 백엔드는 다음과 같은 다양한 데이터 소스를 통합한다:

    - 관계형 데이터베이스
    - 벡터 데이터베이스

4. 벡엔드는 LLM의 원시 출력을 후처리해 개선함으로써, 프론트엔드에 전달하기 전에 응답이 테스트 프로세스의 테스트 컨디션과 일치하도록 보장한다.



## 4.1.2. 검색 증강 생성 (Retrieval-Augmented Generation, RAG)

- (K2) 검색 증강 생성을 요약한다.
- (H1) 주어진 테스트 작업에 대해 검색 증강 생성을 실험한다.

---

사용자 프롬프트 처리 단계에서 RAG 시스템은 다음 2단계 프로세스를 통해 작동한다:

1. **검색**: 사용자 쿼리가 주어지면, 시스템은 이전에 생성된 벡터 데이터베이스에서 관련 정보를 검색한다. 이 검색은 일반적으로 프롬프트의 임베딩과 청크의 임베딩 간의 의미론적 유사성을 기반으로 한다.

2. **생성**: 검색된 정보는 LLM에 전달되어, 기존 지식과 새로 획득한 데이터를 결합한 응답을 생성하며, 결과적으로 더 정확하고 문맥에 맞는 출력이 나온다.



## 4.1.3. 테스트 프로세스 자동화에서 LLM 기반 에이전트의 역할 및 적용

- (K2) 테스트 프로세스 자동화에서 LLM 기반 에이전트의 역할과 적용을 설명한다.
- (H0) LLM 기반 에이전트가 반복적인 테스트 작업 자동화에 기여하는 바를 관찰한다.

---

LLM 기반 에이전트의 자율성 정도는 다음과 같이 나뉠 수 있다:

- **자율적 에이전트**: 사전 정의된 규칙, 강화 학습, 적응형 피드백 루프를 사용해 최소한의 인간 개입으로 독립적으로 작업을 수행한다.

- **준자율적 에이전트**: 출력이 사용자 정의 목표를 충족하는지 확인하기 위해 주기적인 인간의 감독 하에 작업을 수행한다.

다중 에이전트 아키텍처는 각각 특화된 역할을 가진 여러 에이전트가 단일 에이전트보다 더 효율적으로 복잡한 문제를 해결하기 위해 소통하고 조율하는 협업 시스템을 포함한다. 여러 AI 에이전트 간의 이러한 체계적인 협업을 "오케스트레이션(orchestration)"이라고 하며, 여기서 LLM 기반 에이전트는 인간의 추론과 의사결정을 모방해 테스트 작업을 자동화할 수 있다.

# 4.2 미세 조정과 LLMOps: 소프트웨어 테스팅을 위한 생성형 AI 운영화

## 4.2.1. 특정 테스트 작업을 위한 언어 모델 미세 조정

- (K2) 특정 테스트 작업을 위한 언어 모델의 미세 조정을 설명한다.
- (H0) 주어진 테스트 작업과 언어 모델에 대한 미세 조정 프로세스 예제를 관찰한다.

---

소프트웨어 테스팅을 위해 GenAI 모델을 미세 조정하는 것은 다음과 같은 몇 가지 도전 과제를 동반한다:

- 고품질의 작업별 훈련 데이터셋을 사용해 편향되거나 부정확한 결과를 방지해야 한다.

- 다양한 시나리오에 걸쳐 일반화 성능을 유지하기 위해 과적합을 완화해야 한다.

- 디버깅과 검증을 어렵게 만든느 모델 추론의 불투명성을 해결해야 한다.

- 미세 조정 프로세스에 필요한 막대한 컴퓨팅 자원을 관리해야 한다.



## 4.2.2. 테스트 작업을 위한 LLM 배포 및 관리에서 LLMOps의 역할

- (K2) LLMOps와 테스트 작업을 위한 LLM 배포와 관리에서의 역할을 설명한다.

---

LLMOps(거대 언어 모델 운영)는 프로덕션 환경에서 LLM의 개발, 배포, 유지보수를 간소화하도록 설계된 실천법, 도구, 프로세스의 집합을 의미한다.

조직의 테스트 프로세스에서 생성형 AI를 사용하는 방법은 몇 가지 다른 방식으로 달성될 수 있으며, 이는 결정해야 할 LLMOps 항목에 영향을 미친다. 세 가지 가능한 접근법은 다음과 같다:

- **AI 챗봇 사용**: 이 접근법의 주요 고려 사항은 데이터 프라이버시와 보안 리스크를 관리하면서 비용을 최적화하는 것이다. 조직은 필요한 보장이 제공되는 경우 LLM-as-a-Service 플랫폼을 사용하거나, 더 강력한 통제력 확보를 위해 오픈 소스 라이선스 LLM을 사용해 사내 인프라를 구축하고 배포할 수 있다. 데이터 프라이버시와 보안 리스크를 완화하고 운영 효율성을 보장하려면 공급업체의 보장 내용이나 내부 역량에 대한 엄격한 평가가 필수적이다.

- **GenAI 기능이 있는 테스트 도구 사용**: 이 접근법은 AI 챗봇과 유사한 고려 사항(데이터 프라이버시, 보안, 운영 비용)을 가진다. 추가적으로, 조직은 테스트 도구 제공업체가 제공하는 데이터 보안 및 성능 보증을 평가해야 한다. 이러한 테스트 도구는 일반적으로 기존 테스트 프로세스를 보완하므로, 철저한 비용 편익 분석과 리스크 평가가 필요하다.

- **GenAI 기반 테스트 도구 자체 개발**: 이 접근법은 데이터 개인정보 보호 및 보안 위험에 대한 포괄적인 통제와 더불어, 컴퓨팅 자원, 데이터 저장, 직원 교육과 같은 AI 자원 활용에 대한 신중한 계획을 강조한다. 조직은 또한 GenAI에 특화된 개발 항목을 검증하고 유지보수하기 위한 체계적인 프로세스를 수립해야 한다. 자체 솔루션을 개발하려면 LLM 기반 테스트 인프라를 구현하고 배포하는 전문 지식이 필요하다.
