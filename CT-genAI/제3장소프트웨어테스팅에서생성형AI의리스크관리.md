## 3.1.2. LLM 출력에서 환각, 추론 오류, 편향 식별하기

- (K3) LLM 출력에서 환각, 추론 오류, 편향을 식별한다.
- (H1) GenAI를 이용한 테스팅에서 환각을 실험한다.
- (H1) GenAI를 이용한 테스팅에서 추론 오류를 실험한다.

---

다음은 리뷰 또는 리뷰와 자동화된 검증의 결합을 통해 적용되는 일반적인 접근법이다:

**환각 탐지**:

- 교차 검증: AI가 생성한 출력을 기존 문서, 요구사항, 알려진 시스템 동작과 비교한다. 자동화 도구는 출력물을 기존 데이터 소스와 상홓 참조해 불일치하는 부분을 표시하는 데 도움을 줄 수 있다.

- 도메인 전문가 자문: 생성된 콘텐츠의 정확성을 검증하기 위해 해당 분야의 전문가를 참여시킨다. 이들의 전문성을 자동화된 시스템이 놓칠 수 있는 미묘한 통찰력을 포착하는 데 필수적이다.

- 일관성 확인: 생성된 출력이 서로 일관되고 알려진 정보와 일치하는지 확인한다. 자동화된 시스템은 패턴을 식별하고 불일치를 표시하는 데 도움이 될 수 있다.

**추론 오류 탐지**:

- 논리적 검증: 리뷰 주기를 통해 AI가 생성한 콘텐츠의 논리적 흐름(예: 생성된 텍스트 내의 일관성, 조화, 구조화된 추론)이 일관되고 정확한지 평가한다. 자동화된 도구가 도움이 될 수 있지만, 복잡한 경우에는 인간의 판단이 필요할 수 있다.

- 출력 테스팅: 예를 들어, 생성된 테스트 케이스나 테스트 스크립트를 테스트 대상에 대해 실행해 테스트 결과를 검증한다. 이는 생성되는 테스트웨어 유형에 따라 부분적으로 또는 완전히 자동화될 수 있다.

**편향 탐지**:

- 생성된 테스트웨어(예: 테스트 코드나 합성 테스트 데이터)가 정의된 테스트 전략과 커버리지 요구사항을 공정하고 정확하게 반영하고 있는지 검토한다.

- 생성된 LLM 출력에서 과소 표현된 비기능 테스트와 같은 테스트 유형 관련 편향을 평가한다.

## 3.1.3. 소프트웨어 테스트 작업에서 GenAI 환각, 추론 오류, 편향 완화 기법

- (K2) 소프트웨어 테스트 작업에서 GenAI 환각, 추론 오류, 편향에 대한 완화 기법을 요약한다.

---

AI 환각, 추론 오류, 편향 관련 리스크를 완화하기 위한 주요 기법은 다음과 같다:

- **완전한 컨텍스트 제공**: 프롬프트에 모든 관련 정보가 포함되도록 해서, AI가 정확한 결과를 생성하도록 안내하는 포괄적인 컨텍스트를 제공한다.

- **프롬프트를 관리 가능한 단계로 나누기**: 프롬프트 체이닝 기법을 사용해서, 복잡한 프롬프트를 더 작은 단계로 나누고, 다음 단계로 이동하기 전에 각 출력을 체계적으로 검증한다. 이 단계별 접근법은 생성 프로세스 초기에 추론 오류를 탐지하도록 지원한다.

- **명확하고 해석 가능한 데이터 형식 사용**: GenAI가 해석하기 모호하거나 어려울 수 있는 형식을 피한다. 구조화되고 직관적인 형식은 모델이 작업의 본질적인 측면에 집중하도록 지원한다.

- **작업에 적합한 GenAI 모델 선택**: 당면한 작업에 특별히 고안되어 훈련된 LLM을 사용한다.

- **여러 모델 간 결과 비교**: 적절한 경우, 여러 LLM으로 프롬프트를 평가하고 출력을 비교함으로써 출력 오류를 탐지하고 가장 신뢰할 수 있는 결과를 선택하도록 지원한다.



## 3.1.4. LLM의 비결정론적 행동 완화

- (K1) LLM의 비결정론적 행동에 대한 완화 기법을 상기한다.

---

완전한 재현성을 보장할 수는 없지만, 특정 전략이 변동성을 줄이는 데 도움이 될 수 있다:

- **LLM의 온도 파라미터(Temperature Parameter) 설정 조정**: 응답 생성(추론) 과정에서 온도를 낮추면 확률 분포가 좁아져 무작위성이 줄고 더 일관된 출력이 생성된다. 그러나 이는 창의성과 응답의 다양성을 제한해 출력이 더 반복적이거나 지나치게 결정론적이 되도록 한다.

- **랜덤 시드(Random Seed) 설정**: 일부 LLM 구현에서는 난수 생성기에 시드값을 설정할 수 있도록 지원하며, 동일한 의사-난수(즉, 결정론적 무작위 값) 시퀀스가 사용되도록 보장해 재현성을 향상시킨다.

# 3.2 소프트웨어 테스팅에서 생성형 AI의 데이터 프라이버시와 보안 리스크

## 3.2.1. 생성형 AI 사용 관련 데이터 프라이버시와 보안 리스크

- (K2) 소프트웨어 테스팅에서의 생성형 AI 사용 관련 주요 데이터 프라이버시 및 보안 리스크를 설명한다.

---

Gen AI는 민감하거나 개인 식별이 가능한 정보가 포함될 수 있는 대량의 데이터를 처리할 수 있다. 이는 다음과 같은 데이터 프라이버시 우려를 제기한다:

- **의도하지 않은 데이터 노출**: GenAI 모델이 우연히 민감한 정보를 드러내는 출력을 생성할 수 있다.

- **데이터 사용에 대한 통제 부족**: GenAI 도구가 명시적인 사용자 동의나 통제 없이 민감한 데이터를 저장하고 처리할 수 있다. 이는 잠재적인 오용이나 무단 접근으로 이어질 수 있다.

- **규정 준수 리스크**: GDPR(일반 데이터 보호 규정)과 같은 데이터 보호 규정을 준수하지 않고 GenAI 도구를 사용하면 법적 분쟁으로 이어질 수 있다.

또한, GenAI로 테스팅할 때 다음과 같은 특정 보안 리스크가 발생할 수 있다:

- LLM 기반 테스트 인프라는 데이터 침해나 무단 접근과 같은 보안 공격에 취약할 수 있다.

- 악의적인 행위자는 LLM의 취약점(예: 조작 공격)을 이용해 그 행동을 변경하거나 민감한 정보를 추출할 수 있다.

- 공격자는 의도적으로 악의적인 입력 데이터를 주입해 LLM을 오도하고 정확성이나 보안을 훼손할 수 있다.

## 3.2.3. 소프트웨어 테스팅에서 생성형 AI의 데이터 프라이버시 보호 및 보안 강화를 위한 완화 전략

- (K2) 소프트웨어 테스팅에서 생성형 AI 데이터 프라이버시를 보호하고 보안을 강화하기 위한 완화 전략을 요약한다.
- (H0) 제공된 생성형 AI 테스팅 사례 연구에서 데이터 프라이버시와 보안 리스크를 인식한다.

---

GDPR과 같은 데이터 보호 규정은 GenAI의 적용을 명시적으로 제한하지는 않지만, 데이터 수집, 처리, 저장의 합법성, 목적 제한 관련 가능한 일을 제한하는 안전 장치를 제공한다.

이러한 리스크를 완화하기 위해 조직은 다음과 같은 강력한 데이터 프라이버시 조치를 구현해야 한다:

- **데이터 최소화**: 법적으로 허용되지 않는 한 민감한 데이터의 처리를 피하고, GenAI를 활용한 테스팅에서는 필요한 최소한의 민감하지 않은 테스트 데이터만을 사용해 데이터 개인정보 보호 위험을 줄인다.

- **데이터 익명화와 가명화**: 민감한 정보를 마스킹하거나 식별 불가능한 데이터로 대체한다.

- **안전한 데이터 저장과 전송**: 강력한 암호화 및 접근 제어를 구현한다.

- **리소스 교육**: 조직은 GenAI 도구의 책임 있는 사용을 보장하고, 윤리적 실천법을 장려하며, 잠재적 리스크를 완화하기 위해 명확한 교육 프로그램과 정책을 수립해야 한다.

테스팅에 GenAI를 구현할 때 다음과 같은 추가적인 완화 전략을 고려할 수 있다:

- **생성된 결과물의 체계적인 검토**: 인간의 평가는 GenAI 기반 테스트 작업의 품질과 정확성을 보장하는 데 필수적이다.

- **다른 LLM과의 비교 평가**: 주어진 작업에 대해 여러 LLM을 사용해 응답을 비교함으로써 출력물을 평가한다.

- **안전한 운영 환경 선택**: 요구되는 기밀 수준에 따라 조직은 다양한 보안 솔루션을 선택할 수 있다(예: LLM 제공업체의 상용 보안 솔루션 사용, 안전한 클라우드에서 LLM 운영, 조직의 인프라에 LLM 설치 등).

- **정기적인 보안 감사와 취약점 평가**: GenAI 시스템의 약점을 식별하고 해결한다.

- **보안 모범 사례 최신 정보 유지**: 최신 보안 지침 및 기술을 최신 상태로 유지한다.

## 3.4.1. 소프트웨어 테스팅에서 GenAI와 관련된 AI 규정, 표준, 프레임워크

---

다음은 소프트웨어 테스팅에서 GenAI 사용과 관련된 주요 지침의 개요이다:

|이름|유형|설명|소프트웨어 테스팅에서의 적용|
|---|---|---|---|
